# ADR-0015: 精简入口并保留领域草稿所有权

- Status: Accepted
- 日期：2026-10-21
- Decider：用户批准的三批产品精简
- 依据：现役入口、领域恢复契约及对应回归测试

## Context

首次投递不应以配置 AI 为前提。相同待办分散在概览、提醒与设置中，练习与素材入口
存在跳板和重复容器。AppShell 内的大量领域草稿还使退出及桌面更新安全读取难以核对。
精简必须保留来源、确认、幂等、结果未知和恢复，不删除用户历史，也不扩展自动发送权限。

## Decision

- 入门允许先记录投递；AI、简历和对话是可选步骤。收起状态独立持久化，重新打开仍保留
  每一步的真实完成状态。不存在用户明确目标时，不把旧硬编码投递/跟进数量当作目标。
- AI 配置以一次保存提交当前草稿集合；切换 provider 保留各自草稿，连接测试使用编辑值，
  不要求先保存。空白简历与导航命令只承诺实际执行的动作。
- 今日待办是提醒、邮件待审与主动结果的处理入口，设置只管理配置。资格和来源事实见
  [ADR-0012](0012-bound-local-proactive-jobs.md)；展示范围不授予发送权限。
  读取失败或来源复核期间不把旧候选当作当前事实。已发布普通提醒只作折叠历史，
  不能在当前候选到期后重新成为当前待办；失败、未知和生成草稿仍明确可见。
- 面试首页直接选择继续练习、快速模拟、已确认复盘重点和到期题。入口只读，模型调用仍由
  原任务启动；Quick Case、真实 Event、复盘重点和题库记录不互相转换。
- 已确认 Knowledge Note 在参考知识入口管理，并保留冻结来源与版本生命周期；经历故事和
  已确认个人片段留在“我的经历”。面试入口复用同一素材 owner，不自动吸收未确认草稿。
- 设置按通用、AI/隐私、连接/自动任务、备份、诊断分组。诊断展开时才读取/轮询；离线语音
  管理按需首次加载。打开 AI 配置不卸载其他设置草稿，失败、取消、隐私/备份和邮件实验限制保留。
- AppShell 保留现有 canonical task controller 与 generation 授权，JD、谈薪和面试领域草稿
  由 typed hooks 持有。现有 registry 汇总各 owner 的 unsaved/pending/unknown 安全投影；
  不建立第二套会话状态机。同步快照保证同一事件中的连续更新立即可见，关闭页面不丢草稿。
  owner 缺失、抛错或无效读值均阻止更新/重启，不能被当作安全空状态。
- 只删除无生产与动态引用的五个旧 UI 壳，独有安全回归迁到现役 Studio；不按 V01 名称删功能。

## Consequences

入口更少、同一领域只有一个持有草稿的 owner；用户仍可在没有 AI 的情况下使用投递管理。
未知结果与失败不会因导航简化被清除。候选复核期间会短暂显示加载，而不是继续展示可能过期的卡。
此改动无数据库迁移、历史删除、外部凭据操作或新遥测。设置/任务 API 和既有确认权限保持不变。

## Alternatives Considered

1. 只改按钮文字并保留重复入口：实现较小，但无法解决重复容器、来源规则分歧及草稿安全读取，未采用。
2. 引入统一全局工作流/store 重写所有领域：扩大变更面并增加恢复语义回归风险，未采用。
3. 用隐藏页面代替删除全部旧实现：保留无调用写链和重复安全测试，无法降低维护成本；仅对确需保留草稿的现役设置采用保留挂载。
